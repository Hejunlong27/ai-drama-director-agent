# 短剧AI导演Agent · 纯提示词工程包

> 输入原始 `script.json` 剧本，经 9 个模块单向协同，输出多版本 H3 官方格式中文提示词（用于视频生成）。
> 交付形态：分层编排文档（各模块角色 prompt + 输入/输出 schema + 流转/回调节点 + 验收清单 + 测试示例）。本工程不写运行代码，由人类或任意 Agent 编排执行。

---

## 两条铁律（全流程强制）

1. **景别铁律**：人物镜头避免远景，以中景/近景/特写/大特写为主；交代环境用空镜远景（无人物或人物极小）。
2. **溯源约束**：模块输出严格基于剧本原文与前序模块框架，禁止越界创作；所有补充必须能从原文/前序合理推导。台词 100% 逐字复制 `script.json`。

**全局锚点（复用一致性）**：同类型、同字段还有——
- **单集全局 subject_definitions**：人物、场景都必须在 `subject_definitions` 中指定为 `<Subject N>`；同一集锁定同一套全局 subject_definitions，供整集视频段复用（见 `references/iron_rules.md` §2b）。
- **跨剧集导演风格一致性**：非首次生成时，直接沿用前序已确立的导演风格，不重新发明（见 `M02` 步骤 0）。

> 量化判据与注入点见 [`references/iron_rules.md`](references/iron_rules.md)；平台爆款逻辑基准见 `M07`。

## 流程 DAG（单向依赖 + 终审回退）

```
script.json（台词唯一权威）+ 既有导演风格（如有，沿用）
   │
   ▼
[M1 剧种基因分析师] ─────────────────────────┐ 剧种/情绪曲线/节奏图谱/观众触发点
   │                                          │
   ▼                                          │
[M2 导演风格设计师]（沿/定风格，红果TikTok基线）┤ 风格命名/视觉基调/镜头偏好/叙事手法/表演指导
   │                                          │
   ▼                                          │
[M3 分镜设计师] ──────────────┐               │ 本集全局subject清单 + 逐场3-8镜
   │                          │               │
   ▼                          │               │
[M4 音效/布景/灯光设计师]     │               │ 逐镜音效/BGM/布景/灯光（可自分镜推导）
   │                          │               │
   ▼                          │               │
[M5 镜头语言与转场设计师]     │               │ 镜头衔接/节奏/运镜轨迹/视觉母题
   │                          │               │
   ▼                          │               │
[M6 H3提示词输出器·初版]      │               │ 官方六字段初版（备查）
   │                          │               │
   ▼                   第8步  │               │
[M8 观众情绪模拟器] ────┐    │               │ 逐镜情绪+强度+整集曲线+红果TikTok情绪节奏
   │                    │ 不达标退回M2/M3     │
   ▼                    │       │             │
[M9 多版本输出器]       ▼       ▼             │ 输出≥3个风格H3版本（共用全局subject，台词一致）
   │
   ▼
[M7 爆款质检分析师·终审]   ← 第9步·流程最后关卡
   │  对照红果/TikTok爆款判据(P1-P9)逐条质检
   │  不达标 → 退回 M2(导演)/M3(分镜)/M6，直到达标

```

> **顺序**：M1→M2→M3→M4→M5→M6→M8→M9→**M7(终审)**。M7 不再做"节奏检测前置回调"，而是终审批量收尾——M8 先校验情绪节奏、M9 出多版本，M7 最后统一质检并选定可交付版本。

## 用法（编排执行）

1. 从 `script.json` 读入剧本（`episodes[].scenes[].flow[]`），台词以 `.line` 为唯一准绳。
2. 依 DAG 顺序依次执行 M1→M6；**先查既有导演风格若无则 M2 定义、有则沿用**（跨剧集一致）。
3. M8 按红果/TikTok 情绪节奏校验，不达标退回 M2/M3；M9 基于定型分镜出 ≥3 个风格版本（共用单集全局 subject_definitions，台词逐字一致）。
4. M7 终审批量质检（P1-P9），不达标退回 M2/M3/M6 直到达标。
5. **最终交付精简**：若用户未要求中间报告/工作记录，只输出「分镜表 + H3 视频提示词」，不塞过程明细。
6. 逐模块对照 `checklists/acceptance.md` 自检，重点核两条铁律、全局 subject、台词 diff、官方六字段、平台爆款判据、版本一致性。

> 文本提示输出为 Markdown；若用于视频生成工具，按各平台要求将 H3 块作为提示词输入，参考 `references/h3_official.md` 三场景适配。
